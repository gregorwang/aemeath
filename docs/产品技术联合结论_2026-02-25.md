日期：2026-02-25  
范围：README、首次引导、屏幕解读与摄像头、调试入口、角色常驻、视觉架构一致性  
结论性质：本文件为分析与决策文档，不包含代码修改

---

## 1. 执行摘要

本次联合评审确认：你提出的 6 个问题都成立，且不是孤立缺陷，而是同一组产品-技术耦合问题的不同表现。

核心判断：

1. 对外呈现层缺失：README 与快速上手入口不完整，导致新用户无法理解产品价值与用法。
2. 交互预期错位：`你在看什么？`是截图功能，但因“先召唤角色”的链路副作用触发了摄像头，造成隐私感知风险。
3. 行为链路断裂：`调试悲伤安慰/调试无人脸提醒`只触发 TTS，不触发角色可见与 GIF 反馈，形成“对空气说话”。

## 3. 问题逐项结论

## 问题1：README 需要优化（成立）

### 现状
- `README.md` 目前是开发命令+技术亮点，缺少对终端用户的“产品解释”和“上手路径”。
- 启动引导 URL 指向 `#-快速上手`，但 README 里没有对应章节。

### 影响
- GitHub 首屏无法传达产品价值。
- 首次引导打开后用户也找不到清晰操作路径。

### 建议
- P0：重写 README 为“对外展示版”，至少包含：
  - 产品定位与核心价值
  - 功能清单
  - 快速上手（终端用户）
  - 交互入口（托盘/右键/快捷键）
  - FAQ（摄像头/隐私/AI Key）
  - 演示图或 GIF

---

## 问题2：新用户引导与快速上手入口（成立）

### 现状
- 首次启动通过 `first_run` 只触发一次跳转，后续无固定入口。
- 托盘菜单与角色右键菜单中均无“使用指南/快速上手”常驻按钮。
- `docs/` 中没有面向终端用户的短版快速上手文档（`USER_GUIDE.md`偏开发环境与能力说明）。

### 影响
- 新用户“看一次就丢失入口”。
- 认知成本高，功能发现率低。

### 建议
- P0：保留首次引导，但增加常驻入口：
  - 托盘菜单：`使用指南`
  - 角色右键菜单：`快速上手`
- P1：后续可补轻量应用内引导（非阻塞式）。

---

## 问题3：点击`你在看什么？`时摄像头亮（成立）

### 现状链路
1. 触发 `request_screen_commentary()`
2. 若当前 `HIDDEN`，先 `summon_now()`
3. `summon_now -> _enter_engaged()`
4. `_enter_engaged()` 内调用 `_start_camera_tracking_if_needed()`

而屏幕解读本身截图路径使用 `PIL.ImageGrab.grab()`，并不依赖摄像头。

### 结论
- 这是“功能耦合导致的副作用”，不是截图模块直接开摄像头。
- 从用户视角看属于高敏感 UX 缺陷：用户请求截图解读，不应默认点亮摄像头。

### 建议
- P0 方案优先级：
  1. 为屏幕解读请求增加“无 CV 召唤路径”（召唤角色但不启摄像头），或
  2. 屏幕解读请求直接不要求召唤，后台完成截图+语音。
- P1：若保留现行为，必须给出明确提示文案并允许关闭该联动。

---

## 问题4：调试悲伤/调试无人只有语音无角色与GIF（成立，产品缺失）

### 现状
- `trigger_sad_comfort_debug` 与 `trigger_no_face_test_debug` 最终仅调用 `audio_manager.speak(...)`。
- 不会保证角色出场，也不会触发专属 GIF 反馈事件。

### 影响
- 角色隐藏时表现为“对空气说话”。
- 调试按钮无法验证完整体验链路（只验证了语音子链路）。

### 建议
- P0：调试按钮应模拟“完整业务事件”，而非直接调 TTS：
  - 先确保角色可见（必要时召唤）
  - 再触发语音+视觉（状态或粒子）
- P1：在 `GifStateMapper` 增加语义事件（如 `on_sad_comfort`、`on_user_return`）。

---

## 问题5：角色是否应常驻（需产品决策）

### 当前设计
- 状态机以 `HIDDEN` 为常态，按空闲/召唤/被动陪伴短时出现后自动退场。
- 这更接近“事件型助手”而非“常驻桌宠”。

### 建议决策
- 推荐折中方案：新增“可选常驻模式”。
  - 默认：保持当前非常驻，减少打扰。
  - 常驻开：边缘小体积常驻，全屏时自动隐藏。

---

## 问题6：系统性问题（架构层）

### 根因
- 角色可见性、CV 生命周期、屏幕解读触发被绑定在同一状态跃迁上。
- 主角色渲染（EntityWindow）与粒子渲染（GifParticleManager）事件路由不统一。
- 调试入口绕过主链路，导致“能说话但无视觉”。

### 中期方向
- 统一事件层（Event Router）：
  - `UserIntent.ScreenCommentaryRequested`
  - `Affect.SadComfortTriggered`
  - `Presence.UserReturned`
- 在事件层分发到三类执行器：
  - 语音执行器
  - 主角色视觉执行器
  - 粒子视觉执行器
- 调试入口只负责“注入事件”，不直接调用底层 TTS。

---

## 4. 优先级与实施顺序

### P0（立即，体验止损）
1. README 重写并补“快速上手”真实章节。
2. 托盘/右键菜单增加固定“使用指南”入口。
3. `你在看什么？`链路去除摄像头副作用（或最小化影响）。
4. 调试悲伤/无人链路改为“出场 + 语音 + 视觉”完整验证。

### P1（近期，产品一致性）
1. 新增“常驻模式”开关与全屏自动隐藏策略。
2. 为悲伤安慰/用户回归补专属视觉反馈事件。

### P2（中期，架构治理）
1. 统一事件派发层，消除功能耦合与调试绕行。
2. 让自动触发、手动触发、调试触发走同一业务链路。

---

## 5. 验收标准（建议）

1. 新用户首次打开后，任何时刻都能在菜单中找到“使用指南”。
2. 触发`你在看什么？`时，默认不应点亮摄像头（除非用户显式开启联动）。
3. 调试悲伤/无人时，若角色隐藏，必须先可见化，再执行语音与视觉反馈。
4. README 首屏可让陌生访客在 30 秒内理解：这是什么、能做什么、如何开始。

---

## 6. 结语

这不是“某一个函数写错”的问题，而是产品语义、交互预期、运行时资源策略在多个入口上未统一。  
短期先修 P0 可显著改善真实体验；中期通过事件层统一可避免同类问题反复出现。
