Aemeath 项目深度 Review 报告
📊 项目概况
这是一个 Windows 桌面 AI 伴侣应用（"赛博伴侣"），使用 PySide6/Qt 构建，具有 GIF 动画角色、语音交互、摄像头视觉感知、空闲入侵、屏幕评论等功能。代码量约 9000+ 行，测试覆盖 39 个测试文件。

🔴 严重问题（Critical Issues）

1.

main.py
是 903 行的「上帝函数」

main()
函数从第 217 行到第 898 行，接近 700 行，包含了初始化、信号连接、热键注册、语音监听器管理、设置对话框回调、上下文菜单、关机逻辑等全部逻辑。
问题: 几乎无法测试，难以维护。任何单一改动都可能影响全局。
建议: 将

main.py
拆分为：

App
类（初始化和生命周期管理）
HotkeyManager 类（全局热键注册/注销）
VoiceController 类（语音唤醒/PTT 生命周期）
MenuBuilder 类（上下文菜单和托盘菜单构建）2.

Director
类过于庞大 — 1355 行 / 81 个成员

Director
是一个典型的 God Object，承担了：状态机管理、摄像头控制、情绪系统、表情追踪、屏幕评论调度、语音轨迹播放、空闲入侵协调、自动关闭定时器… 几乎所有业务逻辑都在这里。

init
方法就有 150 行，初始化了 30+ 个实例变量。
建议: 按职责拆分成多个 Controller/Mixin：
CameraController — 摄像头跟踪、人脸检测、表情反应
AudioBehaviorController — 音频输出反应相关
ScreenCommentaryController — 屏幕评论调度
TrajectoryController — 语音轨迹播放 3. 双重导入模式极其脆弱
python

、

、

presence_detector.py

gif_state_mapper.py
等多个文件中重复出现。它的根本原因是缺少一个统一的包结构。

建议: 在 src 目录添加

.py
，使用 -m 方式运行（python -m src.main），或在 setup.py/pyproject.toml 中配置正确的 package。4.

audio_detector.py
混合使用 PyQt6/PyQt5/PySide6
python

9.

main.py
中 B 键全局热键会拦截所有 B 键输入
python
user32.RegisterHotKey(None, HOTKEY_ID_PUSH_TO_TALK, MOD_NONE | MOD_NOREPEAT, VK_B)
将 B 键注册为全局热键（无修饰键）意味着用户在任何应用中按 B 都会被拦截，这会严重影响正常使用（尤其在文本编辑器、浏览器中打字）。

建议: 至少使用 MOD_CTRL + B 或其他不影响日常使用的组合。10.

requirements.txt
中包含 pytest
测试依赖不应出现在运行时依赖中。应分离为 requirements-dev.txt。

🟡 中等问题（Moderate Issues）11.

MoodSystem
过于简化
心情值只是一个 0-1 的浮点数，没有持久化。每次重启会回到 0.5。对于一个需要长期互动的 AI 伴侣来说，心情应该被保存。

12.

EntropyEngine

这不需要一个单独的类，可以合并为

13.

ResourceScheduler

只根据是否全屏和是否有用户对话来决定 LLM 是否运行。没有考虑电量、CPU 使用率、网络状况等。

14.

PresenceDetector
的帧计数器没有时间维度
\_face_absent_count 等计数器直接按帧数计算（如 30 帧），但没有考虑摄像头实际帧率。如果 FPS 从 15 变到 5，行为会完全不同。

15. 配置迁移逻辑直接写在

main.py
中

\_migrate_legacy_asr_defaults()
和

16. Director.\_resolve_voice_trajectory_path() 方法过于复杂
    130+ 行的路径解析，遍历多层目录、环境变量和父目录。应该简化搜索策略或缓存结果。

17. IdleMonitor.\_get_idle_time_ms() 的 Tick64 处理有问题
    python
    if self.\_has_tick64:
    current_tick = int(self.\_kernel32.GetTickCount64()) & 0xFFFFFFFF
    用 GetTickCount64() 获取到 64 位值后，用 & 0xFFFFFFFF 截断为 32 位。既然用了 64 位 API，就不应该截断。
