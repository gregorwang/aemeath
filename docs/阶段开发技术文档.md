# Cyber Companion 阶段开发技术文档（v1）

**基于文档**：`docs/产品文档.md`  
**创建日期**：2026-02-25  
**目标**：将产品需求拆为可连续交付的工程阶段，支持按阶段开发、测试、回归与发布。

---

## 1. 统一约束（跨阶段生效）

1. 不做静默降级：功能异常必须显式提示并给出反馈入口。
2. 请勿打扰（DND）为会话态：不持久化到 `config.json`，重启后自动关闭。
3. 屏幕解读允许 3~5 秒延迟：用于“截屏 -> LLM -> TTS”链路，不扩展为实时自由对话。
4. 变更优先低风险增量：单阶段尽量控制在少量文件、可回滚。
5. 每阶段完成后必须执行：
   - `pytest tests/ -v --tb=short`
   - 关键路径手工冒烟（见各阶段）

---

## 2. 阶段总览（执行顺序）

| 阶段 | 对应方案 | 目标 | 预估改动 | 风险 |
|---|---|---|---|---|
| Stage 1 | 方案五：新用户引导 | 首次启动自动打开快速上手 | ~8 行 | 极低 |
| Stage 2 | 方案四：错误提示与反馈 | 统一错误提示 + 日志复制 + 反馈入口 | ~25 行 | 低 |
| Stage 3 | 方案三：请勿打扰模式 | 阻断自动行为，保留手动触发 | ~30 行 | 低 |
| Stage 4 | 方案二：屏幕解读联动 | 解读前确保角色出场 | ~15 行 | 低 |
| Stage 5 | 方案一（简化）：台词自定义 | “编辑台词 + 重载台词”闭环 | ~35 行 | 低 |
| Stage 6 | 方案六：无人脸提醒改造 | 从“离开时说话”改为“回来问候” | ~30 行 | 中 |

---

## 3. 分阶段实施细则

## Stage 1：新用户引导（First Run）

**阶段目标**
- 新安装用户首次启动时，自动打开 README 的“快速上手”锚点并只触发一次。

**范围（In Scope）**
- `BehaviorConfig` 增加 `first_run` 字段。
- 启动流程读取/更新 `first_run`。
- 首次启动通知 + 打开浏览器。

**非范围（Out of Scope）**
- 不做应用内新手引导页。
- 不新增复杂 UI 流程。

**涉及文件**
- `src/core/config_manager.py`
- `src/main.py`

**任务清单**
1. 在 `BehaviorConfig` 添加 `first_run: bool = True`。
2. 在 `_build_behavior` 中读取该字段（默认 `True`）。
3. 在 `to_dict` 中写回该字段。
4. 在 `main` 启动成功通知后判断 `first_run`：
   - 提示欢迎文案
   - `webbrowser.open(...)`
   - 置 `False` 并 `save`

**验收标准**
- 全新配置首次启动：浏览器打开快速上手链接。
- 第二次启动：不再自动打开。
- `config.json` 可见 `first_run: false`（首次后）。

**测试与回归**
- 单测：配置序列化/反序列化包含 `first_run`。
- 手测：删除本地配置后重启两次，验证一次触发。

**回滚策略**
- 若出现启动阻塞，保留字段但暂时注释浏览器打开逻辑。

---

## Stage 2：错误提示与反馈闭环

**阶段目标**
- 所有关键失败有明确通知，不再“自动降级”掩盖错误，并提供反馈渠道。

**范围（In Scope）**
- 统一错误提示文案风格。
- 增加“复制最近日志（50行）”能力。
- 增加“反馈问题”入口。
- 移除 LLM 错误后的自动离线降级逻辑。

**非范围（Out of Scope）**
- 本阶段不新建复杂错误子系统。
- 不改动 LLM/TTS 的业务时序。

**涉及文件**
- `src/main.py`
- `src/ui/tray_icon.py`

**任务清单**
1. 梳理并改写关键错误回调文案（LLM、摄像头、TTS/ASR、配置保存）。
2. 删除 `_on_llm_error` 中自动改离线配置的逻辑。
3. 在 `main.py` 增加 `_copy_recent_logs()`：
   - 读取 log 最后 50 行
   - 写入剪贴板
   - 成功/失败通知
4. 在托盘菜单增加：
   - `复制最近日志`
   - `反馈问题`

**验收标准**
- 触发任一关键错误时，通知文本包含“问题说明 + 反馈引导”。
- 点击“复制最近日志”后可直接粘贴出最新 50 行日志。
- “反馈问题”可打开指定 URL。

**测试与回归**
- 手测模拟网络异常/摄像头占用，确认提示行为。
- 回归：错误后不出现“被动切离线”。

**回滚策略**
- 菜单入口可保留，若剪贴板异常可临时降级为“打开日志目录”。

## Stage 3：请勿打扰（DND）

**阶段目标**
- 一键阻断自动行为（空闲出场、空闲入侵、自动屏幕解读），手动能力保持可用。

**范围（In Scope）**
- Director 持有会话态 `_dnd_mode`。
- 自动路径前置 `if self._dnd_mode: return`。
- 托盘/右键菜单提供可勾选 DND 开关。
- 开关通知与 tooltip 状态提示。

**非范围（Out of Scope）**
- 本阶段不做全局快捷键（后续再评估冲突管理）。
- 不做配置持久化。

**涉及文件**
- `src/core/director.py`
- `src/core/idle_invasion.py`
- `src/ui/tray_icon.py`
- `src/main.py`

**任务清单**
1. `director.py` 新增 `set_dnd(enabled)` 与 `is_dnd()`。
2. 在 `on_user_idle()`、`_on_auto_screen_commentary_timeout()` 添加 DND 阻断。
3. `idle_invasion` 链路增加 DND 判断（或切换时强制 retreat）。
4. `tray_icon.py` 增加 `QAction(checkable=True)` 与 `dnd_toggled` 信号。
5. `main.py` 连接信号 -> `director.set_dnd()`，并发送开关通知。

**验收标准**
- DND 开启后，自动行为全部暂停。
- 手动召唤/手动解读仍可执行。
- 重启后 DND 自动关闭。

**测试与回归**
- 手测开启 DND 等待空闲阈值，验证无自动探头/入侵。
- 手测 DND 下手动触发功能是否正常。
- 回归：关闭 DND 后自动逻辑恢复。

**回滚策略**
- 若影响自动链路稳定性，保留 UI 开关并仅先阻断空闲出场，再逐步恢复其他阻断点。

## Stage 4：屏幕解读与角色出场联动

**阶段目标**
- 无论触发来源，屏幕解读都先确保角色出场，避免“未出场先说话”。

**范围（In Scope）**
- 修改 `request_screen_commentary()` 入口逻辑。
- HIDDEN 状态先 `summon_now()`，等待出场动画后再解读。
- 保持 `_screen_commentary_active_count` 防重入。

**非范围（Out of Scope）**
- 不改 LLM/TTS 内部实现。
- 不调整自动解读调度策略。

**涉及文件**
- `src/core/director.py`

**任务清单**
1. 在入口检查 `EntityState.HIDDEN`。
2. 隐藏时执行召唤并 `QTimer.singleShot(800, ...)` 延后启动解读。
3. 可见时直接走原解读逻辑。
4. 必要时设置 `_suppress_engaged_script_once` 避免出场台词与解读台词冲突。

**验收标准**
- 角色隐藏时手动/自动解读均表现为“先出场后解读”。
- 快速连续触发无重入异常。

**测试与回归**
- 手测 4 类触发：右键菜单、托盘菜单、语音命令、自动定时。
- 回归：解读结束后状态回退与自动消失计时正常。

**回滚策略**
- 若时序冲突，先保留“隐藏时不解读并提示”作为临时兜底，再修复联动逻辑。

## Stage 5：台词自定义（简化版）

**阶段目标**
- 不做复杂 GUI 编辑器，先实现可用闭环：“打开 `scripts.json` 编辑 -> 立即重载生效”。

**范围（In Scope）**
- 菜单新增“编辑台词”“重载台词”。
- 可打开当前角色脚本文件。
- 热重载脚本并刷新 ScriptEngine。

**非范围（Out of Scope）**
- 不做设置面板表格编辑器（QTableWidget 版本）。
- 不做导入/恢复默认高级交互。

**涉及文件**
- `src/ui/tray_icon.py`
- `src/main.py`
- `src/core/asset_manager.py`

**任务清单**
1. `tray_icon.py` 增加两个菜单项与信号。
2. `main.py` 增加回调：
   - `edit_scripts`: 打开当前角色 `scripts.json`
   - `reload_scripts`: 调用资产与脚本引擎刷新
3. `asset_manager.py` 暴露 `reload()`（内部复用 `_load_scripts()`）。
4. 重载后通知用户成功/失败。

**验收标准**
- 点击“编辑台词”可打开正确文件。
- 修改并保存后点击“重载台词”，新台词无需重启即可生效。

**测试与回归**
- 手测台词随机触发路径（空闲、惊慌、回归问候等有脚本的入口）。
- 回归：重载失败时有明确错误提示，不导致应用崩溃。

**回滚策略**
- 若热重载不稳定，临时改为“编辑后重启生效”并保留入口。

## Stage 6：无人脸提醒改造（回来问候）

**阶段目标**
- 由“离开时对空气说话”改为“回来后按离开时长问候”。

**范围（In Scope）**
- 记录离开时间，不在离开时播报。
- 检测回归后按时长分档播报：
  - `<30s` 不说话
  - `30s~5min` 短问候
  - `5~30min` 中问候
  - `>30min` 长问候
- 保留冷却，避免频繁刷屏。

**非范围（Out of Scope）**
- 不引入新视觉模型或置信度算法。
- 不重构整条 gaze 管线。

**涉及文件**
- `src/core/director.py`

**任务清单**
1. 调整 `_maybe_trigger_no_face_test()` 语义为“记录离开与回归判定”。
2. 新增或复用问候方法（例如 `_greet_user_return(away_seconds)`）。
3. 保持原有 cooldown 机制。
4. 增加关键日志，便于排查误触发。

**验收标准**
- 用户短暂转头（<30s）不触发问候。
- 离开后返回按分档文案触发一次问候。
- 无明显重复播报。

**测试与回归**
- 手测低光、快速进出画面、长时间离开等边界。
- 回归：不影响悲伤安慰与基础 gaze 更新逻辑。

**回滚策略**
- 若误判过高，可临时提升阈值到 60s 并只保留短问候分支。

## 4. 跨阶段工程执行规范

1. 提交粒度：每阶段独立提交，禁止跨阶段混改。
2. 测试基线：每阶段至少执行一次 `pytest tests/ -v --tb=short`。
3. 日志基线：关键动作加可检索日志前缀（如 `[DND]`、`[ScreenCommentary]`）。
4. 发布基线（涉及打包时）：
   - 使用 `requirements-build.txt` + `build.spec`
   - 构建后启动 `dist/CyberCompanion/CyberCompanion-core.exe`
   - 检查 `%LOCALAPPDATA%/CyberCompanion/logs/app.log` 无启动级致命错误
5. 文档同步：每阶段完成后更新 `docs/变更报告_YYYY-MM-DD.md` 记录结果。

---

## 5. 阶段入口建议（下一步）

按顺序从 Stage 1 开始，不并行跨阶段开发。  
每完成一个 Stage，先做回归再进入下一个 Stage，避免状态机类问题在后续叠加放大。
